# Design — qwen38-dflash2-recipe

## Context

See proposal.md — Why. Qwen's MTP round is recipe-owned because its target verifies through `PreparedVerificationState` (QSA ring, GDN records, PLE history; `ignition/recipes/qwen38/speculative_state.py:38`), not the paged `Metadata` the shared `PreparedParallelDraftRound` builds for its target (`ignition/components/parallel_draft.py:125`, `:144`). The shared round already has a proposal-only mode with no target decoder, context, or verifier (`:118`, `:301`) whose outputs (`drafts`, `probabilities`, `valid`, `copy_mask`, `candidates`) a separate verifier consumes (`ignition/components/packed_speculation.py:84`); only its admission runs the paged `PreparedBatch` validator, which rejects every page on a pool whose `memory_capacity[1]` is 0 (`ignition/components/paged_batch.py:188`). Nemotron's DFlash block (`ignition/recipes/nemotron_h/dflash.py:42`–`:191`) is a Qwen3-architecture sliding-window draft over a per-row E4M3 ring — the same architecture as `DFlash2DraftModel` (`ignition/reference/qwen38_dflash2.py:11`) minus the attention sink, NVFP4 weights, and the LiLiCorr lattice.

## Goals / Non-Goals

- Goal: `ignition export qwen3.8-flash-dflash2 --gpus 0` produces a package `flare run` serves with up to seven DFlash2 drafts per round, adaptive widths 1..8, `--history-drafts` admitted.
- Goal: the prepared draft block, selector, and tapped features reproduce the spike's reference (`ignition/reference/qwen38_dflash2.py`) within measured BF16 repeatability, so the spike's acceptance carries to the recipe.
- Goal: qwen38 (MTP), qwen38_dense, and nemotron_h keep byte-identical behavior; every edit to their modules is an optional parameter defaulting to today's value or an import move.
- Non-goal: served-throughput comparison against the MTP package (change 3); TP2/TP4; mixed prefill+decode rounds; the Nemotron compiled-forward fault.

## Approach

1. `ignition/components/dflash_draft.py` (new, lifted from `nemotron_h/dflash.py:24`–`:191`): `DraftScratch.allocate(tokens, rows, hidden, vocab, device, buffers)` (activations, normalized, hidden, logits, local_logits); `Rotary`; `DraftForwards` (decoder, context, draft, markov=None); `PreparedContext(draft_weights, auxiliary, rings, *, window, epsilon, rotary, session, name, workspace, buffers)` with `__call__(auxiliary, positions, rows, live)` taking per-token logical positions, state rows, and a live mask — the caller computes `live` (including the window-recency guard `offset >= count - window`) before the slot, and the slot is `torch.where(live, row * window + position % window, -1)` exactly as `:72` today; `DraftAttention(weights, source, metadata, rings, config, *, sink=None, …)`; `DraftMLP` and the context/fc projections bound through `prepare_projection` (`ignition/components/linear.py:21`) so BF16 tensors take `UnquantizedProjection` and NVFP4 weights keep `QuantizedProjection`; `PreparedDraftBlock` running embedding → layers → final norm → head and leaving the selector to the recipe. Rings are passed as tensors `[rows, window, kv_heads, head_dim]`, not fetched from a pool.

## Decisions

- Proposal-only shared round + Qwen verifier, not a copied propose loop — the drafter path (selector, proposal distributions, rng, copy substitution, broadcast) stays one implementation and follows `packed_speculation.py`'s split precedent; the widenings are an owner-supplied admission and a draft page-table width. Alternative rejected: a full Qwen DFlash round re-implementing `propose()` — a second copy of ~120 lines the history-drafts port just unified.
- Lift the draft block to `ignition/components/` rather than importing from `nemotron_h` or copying — AGENTS.md puts reusable mechanisms in components and forbids copying between recipes; the second caller exists today; Nemotron keeps its behavior under its existing CUDA tests. Alternative rejected: `qwen38_dflash` importing `nemotron_h.dflash` — the sink, NVFP4 projections, and lattice coupling would need the same widening inside another recipe.
- Rings in the state row as E4M3 `[2048, 8, 128]` per layer (20 MiB/row), restored as plain state — matches Nemotron's and Kimi's storage contract; DFlash2's context is aligned with consumed tokens (lag 0), so no lag-one transfer path. Alternative rejected: paged draft K/V with `draft_page_tables` — DFlash2 attends a fixed window, and a ring is what the shared storage contract already expresses.
- Stream mean in the decoder tap, fc unchanged — a view-mean fuses under Inductor and keeps `fc.weight` at its checkpoint shape; folding the mean into a `[2560, 51200]` fc would quadruple the weight. The tap runs on the residual the canonical `_layer_hook` publishes, which `qualify/layer_comparison.py` already measures against the prepared decoder.
- `mtp=True` default in `HybridStateLayout.build` keeps every existing layout byte-identical; the DFlash layout is `mtp=False, speculative_tokens=7` so GDN/PLE/QSA histories keep the seven-token speculative widening the verifier needs.
- Own identity for the new recipe — qwen38's `_identity` (`bootstrap.py:210`) omits recipe name, draft, and row bytes, and Helios keys prefix-cache digests on it; sharing it would let an MTP package and a DFlash package match each other's rows. qwen38's own identity is left as is (changing it re-keys every existing package) and noted in `docs/TODO.txt`.
- TP1 only and `mixed_prefill=False` — the draft is unsharded (no `PreparedShardedEmbedding`/all-reduce path) and the mixed round reads the MTP owner; both are change-3 candidates once the served comparison exists.
- Draft fetched into the hub cache by pinned revision — one resolution path, as LiLiCorr; the operator's `--local-dir` copy is not read.

## Risks / Trade-offs

- [Tap differs from the features DFlash2 was trained on] → the spike used canonical `_layer_hook` outputs; task 13's GPU-0 comparison gates export, and the acceptance tool can re-run on the prepared tap if the bound fails.
- [GPU 0 hosts the owner's Qwen instance] → the tap check and export are operator-timed; every other test runs on GPU 1.
- [`PreparedVerificationState` requires `speculative_tokens > 0` in the layout for the QSA ring] → the DFlash layout keeps `speculative_tokens=7` with `mtp=False`; a `-no-mtp` catalog still captures width-one rounds as decode (`docs/model-development.md:280`).
- [Chunked prefill longer than the window] → the context keeps only each request's last 2048 positions per chunk (component guard), and later chunks overwrite older ring slots — ring semantics.
- [Dead tokens' `request_ids == -1` wrap to the last row under Python indexing] → the live mask is computed before the slot and the slot is `-1` for dead tokens; the CPU round test covers it.
- [Nemotron served path unverifiable on this host] → the lift is covered by `tests/recipes/nemotron_h/test_dflash_cuda.py` (56 pass here) and a declaration test; served Nemotron stays BLOCKED as recorded in `openspec/debug/nemotron-serve-device-error.md`.
- [Selector tie-breaking] → `PreparedCandidateSelector` scatters the shortlist into the full vocabulary (`candidate_selector.py:24`); the reference's lowest-id tie rule matches (`qwen38_dflash2.py:231`).
- [E4M3 ring quantization versus the BF16 reference] → the CUDA parity test round-trips K/V through the ring and records the measured bound; a bound outside BF16 repeatability is a finding, not a tolerance to relax.

- **Target checkpoint.** The operator confirmed the target is `~/models/local-inference-lab/Qwen3.8-Flash-Next-NVFP4-MXFP8-CSF-QAD`, a `--local-dir` snapshot of `local-inference-lab/Qwen3.8-Flash-Next-NVFP4-MXFP8-CSF-QAD` at `dc5b8ab2fa14bc4fecd6886273b7ebc6095662e2` (its `.vllm_console_revision.json`). Decision (operator, chosen over an export flag and a per-model config key): the recipe declares the CSF-QAD repository and revision itself, with stored/device bytes measured from its container manifest, as every other alias does; the operator places that snapshot in the hub cache once. Consequence: the two recipes no longer share a repository, so item 12's ambiguity error has no live case and is withdrawn — resolution returns to HEAD's behavior and the tests that encoded item 12 are reverted.
- **E4M3 rings stand, measured.** Task 6.1's parity test failed against the BF16 reference (hidden 0.12–0.38 relative on fabricated features; the selector and every non-attention stage exact). The operator chose to measure on real features first: the spike's 18 cases were re-traced through the canonical reference on GPU 0 (trace digest `966ca48a32cf9823`, identical to the spike) and `qualify/dflash2_acceptance.py measure` ran the DFlash2 arm with BF16 and with E4M3-rounded key/value (`--e4m3-kv`, rounding the reference's `_kv` exactly as the prepared rings and staging do): code_edit acceptance 3.760 (w4) / 6.537 (w8) for both; overall 3.020 / 4.025 (BF16) vs 3.037 / 4.051 (E4M3); MTP 3.654 / 5.622 and 2.961 / 3.795. E4M3 costs nothing on this checkpoint's features, so the storage contract of item 4 stands and the random-feature failure was an artifact of the test inputs (the block amplifies half-ulp noise ~30x on random features). The parity requirement is re-based: compare against the reference with E4M3-rounded key/value, on a real trace when available (`FLARE_DFLASH2_TRACES`, the precedent of `tests/reference/test_qwen38_dflash2.py`), fabricated otherwise; the bound stays at measured repeatability. Raw measurements are kept under `qualify/results/dflash2-acceptance/`.
- **Parity bounds follow measured repeatability (task 6.2).** Against the E4M3-rounded reference on real tapped features (trace `chat-capacity`, cuts 198–430, batches 1 and 4) the prepared block's rings land at 1.26e-2 / 1.54e-2, hidden at 1.6e-2–4.0e-2, logits 1.8e-2–3.9e-2, and the shortlist and walked tokens equal the reference on 15/15 rows. The rounded reference itself moves 1.2e-2–4.3e-2 under one-ulp BF16 noise on its inputs or an FP32-projection variant, because 4–8 percent of ring elements sit one E4M3 bin apart; the 1e-2 the tasks carried from the Nemotron test is below that repeatability and no BF16 implementation of this contract can meet it. AGENTS.md requires numerical bounds to follow measured repeatability, so the test asserts rings ≤ 2e-2, hidden and logits ≤ 5e-2, and exact shortlist/walk agreement on real features; fabricated features keep the selector, ring, and dead-token assertions and a measured 0.21 hidden/logits bound with the ~30x amplification recorded. The acceptance measurement above is the end-to-end check that the contract preserves the spike's result.
- **Tap divergence is the prepared decoder, acceptance holds on prepared features (task 8.1).** On GPU 0 the compiled prepared decoder's tapped features differ from the canonical reference by 0.03–0.06 (layer 5) growing to 0.16–0.41 (layers 35/45) relative across the 18 traces (`qualify/results/dflash2-tap-check/all-cases.json`); the eager control (`--no-compile`) matches the compiled profile, so this is the b12x decoder (NVFP4 experts, `auto` activation precision) versus exact canonical arithmetic, not the taps and not Inductor. Item 13's fallback was applied: `qualify/dflash2_tap_check.py --dump-features` prefilled every trace through the prepared tapped decoder and `measure --e4m3-kv` on those features gives code_edit 3.744 (w4) / 6.394 (w8), overall 3.004 / 3.989 (`qualify/results/dflash2-acceptance/dflash2-prepared-e4m3-kv.json`), against 3.760 / 6.537 and 3.037 / 4.051 on canonical features and MTP's 3.654 / 5.622. The draft tolerates the prepared decoder's divergence; export proceeds.
