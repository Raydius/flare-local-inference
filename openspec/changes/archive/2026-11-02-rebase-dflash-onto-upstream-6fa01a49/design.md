1. **Backups first.** Tag `backup/pre-rebase-20261102-<ref>` for `deploy`, every `patch/NN`, `base/current`, and `wt/dflash-s-e2vk` (the fork's convention, FORK.md). The old `deploy` tip `4718693a` is the pivot the branch rebase needs.
2. **Patch stack through the fork's script.** From the main checkout (on `deploy`): `scripts/fork/rebase.sh 6fa01a49` (`git rebase --onto 6fa01a49 base/current deploy --update-refs`). Two conflicts: `ignition/planning.py` keeps patch/06's `declared` context message and upstream's `world_sizes` filter for `--vocabulary-parallel-sampling`; `tests/cli/test_models.py` keeps `qwen3.8-flash-yarn4` in upstream's alias tuple (which ends in `muse-spark-open-nvfp4`). Constraints carried (AGENTS.md): no behavior change to Helios, contracts, recipes, or package format in any resolution; comparative numbers from `flare run` packages only; exports and serving in the container from a committed ref; no environment-variable switches; the owner alone stops the GPU 0 instance; `main` is never merged into.

Not in scope: folding `dflash_draft.py` into `components/dflash2.py`; adopting packed verification for `qwen38_dflash`; any patch retirement.

Decisions the review settled (recorded here so apply does not re-derive them):
- The `c977814b` merge carries no branch-only delta: `git merge-tree --write-tree c977814b^1 c977814b^2` reproduces its tree `ca07e4d5` exactly, so the rebase may drop it.
- `draft_argmax` is gone upstream end to end (`git grep draft_argmax upstream/main -- ignition` finds nothing: the kimi3 producers and the shared-round consumer were both removed by #135); deleting our `argmax` block follows upstream, and kimi3 needs no equivalence test of a path that no longer exists on either side.
- `torch 2.14.1+cu132` and `triton 3.8.0` are identical in both locks; the re-lock changes only `flashinfer-python`.
- `.github/workflows/native-serving.yml` changed upstream only; it auto-merges and is not run here.
- Upstream `f0745cd1` touches `scripts/setup_preparation.py` (the preparation-environment setup refreshes FlashInfer's locked revision from `@main`); the container build installs from `uv.lock`, and `uv lock --check` in the image proves the pinned sha is what ships.
