## Decisions

- Component unmodified, adapter in the recipe — an upstream recipe PR must import the component as-is; any edit to `dflash2*.py` (e.g. a `page_tokens` parameter or FP32 rotary) is a separate upstream change with its own evidence.
- Dedicated `context_buffers` / `draft_buffers` pools rather than the graph cursor — the component forks the cursor it receives without joining (`dflash2.py:57`, `:210`); on the graph cursor its scratch would alias the sampling scratch allocated next (safe only by call order). Upstream's pools make the lifetimes explicit.
- Per-round draft scratch rather than once-at-capacity — memory parity with today and the declared costs stay valid (item 4).
- Region rename to upstream's names rather than a name-translating accessor — one convention for the same storage across recipes; the rename is free because the package is re-exported anyway.
- Rotary comparison (requested): both are NeoX rotate-half over the full head with `theta^(−2i/d)`; the component computes `values·cos + rotate_half(values)·sin` in BF16 with BF16 cos/sin (`dflash2.py:37`–`:41`), the deleted block in FP32 with BF16-rounded cos/sin (`dflash_draft.py:67`–`:71`), which is the reference's form (`reference/qwen38_dflash2.py:77`). The fold adopts the component's; the parity test measures the consequence. Rope scaling is not touched.

## Risks / Trade-offs

- [The component's BF16 rotary and double-rounded `Qwen3RMSNorm` move the rings past the recorded 2e-2 or hidden/logits past 5e-2] → the parity task reports the measured values and stops the change for the owner; no bound is relaxed and the component is not forked. Candidate follow-ups, both outside this change: an upstream defect PR with the measurement, or bounds re-derived from the component's own repeatability. Shortlist and walk equality on real features remain hard requirements.
- [Served medians drop at concurrency 1 or 8] → trials are compared to 329.1 / 516.5 with offered/accepted drafter counts beside them; a drop over 5 % is a finding reported to the owner, not absorbed; the §9 repetition spread (about ±8 %) is the noise reference.
- [Export OOM from undeclared scratch] → per-graph scratch from shared-chunk pools (item 4); the memory report's new pool entries are checked against the previous entry's `free_device_bytes`.
- [Cursor aliasing in the mixed graph: the prompt context and the round's context both come from `context_buffers` cursors] → each context writes every scratch tensor before reading it in one call and runs at a different point of the graph; a retained value must never be placed in a context cursor (recorded here for apply).
- [Derivative-recipe drift] → the rebase trap applies; `bootstrap.py` is otherwise untouched by this change.

## Revisions

- 2026-11-03, task 3.2 — the parity run held every bound, the shortlists, and the selector, but 2/12 batch-4 real rows left the reference's walk at near-ties (gaps 0.1053 and 0.0207). Measured on the reference alone (`~/.cache/fold-gpu/repeatability.py`, log `repeatability.log`): under one BF16 ulp of noise on its features or block inputs the reference's own walk flips at exactly those positions (18 of 192 draws, largest flipped gap 0.1053, one further row at 0.0715), so an exact walk is not a repeatable property of this reference. Operator decision (option 1 of the apply report, "Ok i agree"): the walk criterion is re-derived from that measurement — a real-feature walk may leave the reference's only at a position whose reference top-two gap is at most the recorded tolerance (`NEAR_TIE_GAP = 0.11`, measured 0.1053), with the prepared token the reference's choice within the gap; shortlists and the selector stay exact; the served requalification remains the gate for acceptance. Spec delta and `test_draft_cuda.py` updated accordingly; no other bound moved.
