# Design — upstream-muse-glimmer-pr

## Approach

- Branch: `git fetch upstream`, record the tip, then `git worktree add /tmp/glimmer-pr -b pr/muse-glimmer upstream/main`. The main checkout stays on `deploy`; the worktree shares `core.hooksPath=.githooks`, so the design-review hook runs on every commit.
- Path set: the Glimmer-only files (`ignition/recipes/muse_glimmer_nvfp4/**`, `ignition/reference/muse_glimmer.py`, `helios/src/frontend/images/muse_glimmer.rs`, `tests/recipes/muse_glimmer_nvfp4/**`, `tests/frontend/test_muse_glimmer.py`) plus the shared files of proposal items 1-9 and 12. Files whose fork history is Glimmer-only take the whole-file diff; the three mixed-history files (`helios/src/model/tests.rs` — history-drafts tests from `95752d66`/`6657f7e5`; `docs/model-preparation.md` — qwen38_dflash sections from `8046cf12`, `890180c1`, `9f764425`, `a75e845d`; `qualify/speculative_benchmark.py` — probe changes from `25640c8d`, `20a8d055`, `a75e845d`) take only the hunks of the Glimmer commits (`git log -p --format= <glimmer shas> -- <file>`). The gate before any commit: `git log --format=%s 585159c9..deploy -- <file>` names only Glimmer/passkey commits for every whole-file pick.
- Commit 1 (recipe) is the fork's Glimmer state before the 1M-context change: `git diff 585159c9 6ea1c9c2 -- <path set>` applied with `git apply --3way`. Excluded by path: `openspec/**`, `.claude/**`, `docs/TODO.md`, `qualify/results/**`, `qualify/long_context_passkey.py`, `qualify/dflash2_long_context.py`, `tests/reference/**`.
- Commit 2 (context) is `git diff 6ea1c9c2 d0093957 -- <path set>` — `recipe.py` context 1048576, `bootstrap.py`, `test_config.py`, `test_preparation.py`, `test_dflash_cuda.py` (the 4e-2 hidden-row bound), the Glimmer lines of `docs/model-preparation.md` — plus `qualify/speculative_benchmark.py:32` `width="([1-8])"` → `([0-9]+)` so upstream's benchmark counts width-16 rounds, pinned by a new `round_metrics` case in a new `tests/qualify/test_speculative_benchmark.py` (no upstream test covers `_ROUND`; the case is the fork's `test_draft_counts_reads_width_16_rounds` reduced to `round_metrics` over a two-line metrics delta).
- Fork-only removals in commit 1's tree before committing: `recipe.py:21` drops `draft = plan.draft_model` and its comment (the `snapshot_download` of the pinned z-lab drafter is unconditional); `recipe.py:72` drops `draft_files=(...)` (a fork-only `Recipe` field — `Recipe.__init__` would raise `TypeError` at import and take every CLI command and test with it) and `recipe.py:27` passes the literal `allow_patterns=("config.json", "model.safetensors")` (upstream's `tests/cli/test_draft_checkpoints.py:52` asserts that tuple); `tests/recipes/muse_glimmer_nvfp4/test_draft_weights.py:18,65` replaces `DFlash2Reference.expected_shapes` (fork-only `ignition/reference/qwen38_dflash2.py`) with a local `expected_shapes(config)` helper producing the same 81-tensor dict; `tests/cli/test_draft_checkpoints.py` keeps the three `muse_glimmer_nvfp4` parametrizations and drops `test_a_draft_folder_replaces_the_pinned_download`'s Glimmer row and the `_dflash_plan(name=)` widening; `tests/cli/test_models.py` appends only `'muse-glimmer-30b-nvfp4'` to upstream's alias tuple; `ignition/recipes/__init__.py` adds only the `muse_glimmer_nvfp4` import and tuple entry.
- First gate on the branch, before any test suite: `PYTHONPATH=/tmp/glimmer-pr .venv/bin/python -c "from ignition.recipes import recipes; print(len(recipes()))"` and `pytest --collect-only tests/recipes/muse_glimmer_nvfp4 tests/frontend/test_muse_glimmer.py` — a fork-only name surfaces here as an ImportError/TypeError rather than as a skipped test.
- `ignition/preparation/runtime_package_pb2.py` is regenerated, not patched: `PATH=/tmp/protoc-bin:$PATH protoc --proto_path=helios/proto --python_out=ignition/preparation helios/proto/runtime_package.proto` (helios/manifest.md:379; `/tmp/protoc-bin/protoc` is libprotoc 35.1, upstream's `_pb2.py` header reads Protobuf Python 7.35.1 — same major).
- Commit messages follow upstream's prose skill (problem, behavior, technical reason, compatibility, validation; no history) and carry `Signed-off-by: Ray Dollete <ray@raydollete.com>` (`-s`) and `Design-Signed-Off-By: Claude Fable 5.1 (claude-fable-5-1); design-review=<sha256 of git show :docs/design-review.md, first 4 hex>` (`4d3a` at `972e28e4`; recomputed at commit time) after reading the staged checklist and `.agents/skills/repo-prose/SKILL.md`. Each message states the package-format addition (`MUSE_GLIMMER_IMAGE_PREPARATION = 10`, `MuseGlimmerImageSettings`; additive; an engine without the arm refuses a Glimmer package with "missing protobuf image profile", existing packages load unchanged) and authorship (designed and implemented with Claude Fable 5.1; no CUDA/Triton/CuTe/PTX kernel; the Spark attention change is a Python projection factory writing disjoint regions of `scratch.projected`).
- Validation on the branch, from the fork's `.venv` with `PYTHONPATH=/tmp/glimmer-pr` and cwd `/tmp/glimmer-pr` (as `upstream-rope-pr` task 2 ran): `tests/recipes/muse_glimmer_nvfp4 tests/frontend/test_muse_glimmer.py tests/qualify tests/cli/test_models.py tests/cli/test_draft_checkpoints.py tests/cli/test_planning.py tests/preparation tests/recipes/test_gemma4.py tests/recipes/test_muse_spark_attention.py tests/recipes/test_vision_scratch.py -m 'not cuda'`, and `cargo test --manifest-path helios/Cargo.toml --features server --lib frontend::images`, `--lib runtime_package`, `--lib model::tests` with `PROTOC=/tmp/protoc-bin/protoc`. Baseline: the pristine worktree `/tmp/upstream-main2` (at `0009b89d` today) moved to the recorded tip with `git checkout --detach <tip>`, same suites; the criterion is "no failure the baseline lacks" plus the Glimmer cases absent on the baseline. Peak RSS under a 14 GiB watchdog on the pytest pid; the full CPU suite ran at 2.4 GiB on the fork.
- Skip audit: the CPU run records which Glimmer tests executed and which skipped on their gates (`FLARE_MUSE_GLIMMER_SNAPSHOT`, `FLARE_RUN_CUDA_TESTS`, `FLARE_MUSE_GLIMMER_DFLASH2`, `FLARE_MUSE_GLIMMER_IMAGES`, the hub cache row in `test_frontend_metadata.py:191`, `cargo build --bin test_frontend` for the frontend test); the PR body lists the skipped set as unrun.
- GPU: not run on the branch. The body reports the fork packages' evidence by package id — console-launched `gb202-tp1-202611070323` (image `local/flare-ignition:c4f4fa7c`): 22 width-16 rounds, 99 tokens, 77 of 122 drafts accepted; the 1M export served for the passkey grid: 15 cells, 14 pass at 256 output tokens and the 1,000,000 × 0.9 cell passes at 1,024 (`qualify/results/glimmer-passkey/` on the fork); the DFlash2 oracle parity test on GPU 0 (`1 passed`, hidden-row bound 4e-2) — and states that the rebased branch has not been exported or served, naming `ignition/preparation/compilation.py` (the fork's `80946209` and upstream's `fa0eadad` lower deferred copies differently; Glimmer's graphs were captured under the fork's lowering).
- Push: `git -C /tmp/glimmer-pr push --force-with-lease origin pr/muse-glimmer`; never `main`, `deploy`, or `upstream`.
- PR body: written to `openspec/changes/upstream-muse-glimmer-pr/pr-body.md` (the vault is not mounted on this host), reviewed against the prose skill, naming the #212 alias-list overlap, the two-commit separability, and the open question a reviewer will ask — `draft_config.py` re-derives the DFlash2 configuration instead of calling upstream's `DFlash2Config.from_dict` (`d68ed8f5`); the operator opens the PR with `gh pr create --head Raydius:pr/muse-glimmer --base main --title ... --body-file ...`.
