# Design — rebase-pr229-runtime-core

## Approach

See proposal.md — Why. Code work happens in a new worktree, `~/models/.cache/pr229-rc/tree`, on local branch `pr/muse-glimmer` (`5264a595`, the same commit as `origin`). Docker cannot mount `/tmp`, so the worktree is not there. A pristine worktree of the target, `~/models/.cache/pr229-rc/base`, is the baseline. The `deploy` checkout changes only under this change directory. `T` below is the `upstream/main` tip fetched at the start of apply (`abd56461` at planning).

1. **Retarget, then rebase commit by commit.** `git fetch upstream`, record `T`, and re-probe the conflicts with `git merge-tree`. If `T` is not `abd56461`, its new conflicts are resolved by the same rules. Then run `git rebase T`. Commit 1 (`fdfbeb29`) carries almost every conflict. It is resolved by path class:
   - **Glimmer-owned paths** (`ignition/recipes/muse_glimmer_nvfp4/**`, `tests/recipes/muse_glimmer_nvfp4/**`): start from `deploy`'s file, which already runs the per-call-metadata port (`b5db759a`, Fable 5.2) and the core renames (`63808d0b`, `6645fa2e`'s `mtp_only`). Reverse-apply this path's hunks of PR commits 2 and 3 (`git diff 5264a595 fdfbeb29 -- <path> | git apply`), so commit 1 keeps commit 1's context and concurrency values and commits 2 and 3 replay their own diffs. Remove the fork-only `plan.draft_model` / `Recipe.draft_files` code. Restore the PR-only W4A4 input-activation check and its tests from `fdfbeb29`. New Glimmer files on `deploy` (`attention.py`, `test_attention_cuda.py`, `test_functional.py`) join commit 1.
   - **Shared paths the PR widens** (`ignition/components/dflash2.py`, `ignition/preparation/{checkpoint,quantization,frontend}.py`, `ignition/recipes/{__init__,gemma4/config,muse_spark/contract,muse_spark/frontend}.py`, `qualify/speculative_benchmark.py`, `helios/src/frontend/images/{mod,packing,conditioned}.rs`, `helios/src/model/{contract,tests}.rs`, the tests in proposal Blast Radius item 5): take `T`'s text and re-apply only the PR's own hunks, sorting each hunk by origin rather than by path. A hunk in neither `T` nor `git diff d2b5c5f3 5264a595` is dropped. `deploy`'s `6b68b9b4` resolutions (`~/models/.cache/rebase-6b68b9b4/resolutions.md`) are a reference, never a file to copy. `deploy`'s `quantization.py` would make the shared parser require input activations for Gemma 4 too. The PR's `dflash2.py` hunk is dropped: on `T`, `DraftScratch` already has no `block_size` default, and the hunk's context now matches Spark-only `PooledDraftScratch`. A recipe-wide test that `T` added after the PR's base gets the Glimmer entry it needs (`tests/cli/test_mtp_only.py`, as `deploy`'s `a1051e26` did).
   - **Spark attention** (`ignition/recipes/muse_spark/attention.py`, `tests/recipes/test_muse_spark_attention.py`): `T`'s text. The PR no longer touches them.
   - **Protobuf**: the PR's `runtime_package.proto` additions go into `helios/proto/runtime_core.proto` at number 11 (`MUSE_GLIMMER_IMAGE_PREPARATION = 11`, `MuseGlimmerImageSettings muse_glimmer = 11`). `runtime_package_pb2.py` stays deleted. `runtime_core_pb2.py` is regenerated with `~/models/.cache/protoc-35.1/bin/protoc -I helios/proto --python_out=ignition/preparation helios/proto/runtime_core.proto`, after checking that the same command on `T`'s proto reproduces `T`'s pb2 byte for byte. The PR's reader hunks in `helios/src/runtime_package/{describe,protobuf}.rs` move to `helios/src/runtime_core/`.
   - **Docs**: `docs/TODO.md` gains `deploy`'s fold-back entry for Glimmer's attention. In `docs/model-preparation.md`, the Glimmer section uses "core" vocabulary and states image number 11.

   Commits 2 and 3 replay. Their conflicts are confined to the lines each commit changes (context, concurrency, packed capacity, graph inventory, `tests/cli` expectations). The recipe-free `qualify/speculative_benchmark.py` width fix replays unchanged. A stopped commit is rebuilt with `git commit-tree` from the original message and author, because a plain `--continue` meets the hook, which rejects the stale digest.
2. **Authorship boundary.** AGENTS.md bars Claude Opus 5.5 from changing projection packing, fused arithmetic, stream overlap, or scratch aliasing in optimized paths. In Glimmer's `attention.py`, `decoder.py`, `dflash.py`, and `bootstrap.py`, Fable 5.2's `deploy` text is carried byte for byte except for the named removals (fork-only flag, renames). Any further edit those files need goes to a Claude Fable 5.2 sub-agent (Agent tool, `model: fable`).

   The coordinator builds the chain with `git commit-tree`, keeping authors and dates, after `.githooks/commit-msg` accepts each message. The operator reads the drafts. Then: force-push with lease on `5264a595`, `gh pr edit 229 --body-file`, one `gh pr comment`, and a check that `headRefOid` equals HEAD and the PR reads `MERGEABLE`.

**Decisions**
- **Fold the port into commit 1 rather than adding a fourth commit.** Each commit must prepare on `T`. A commit 1 still on the bound-buffer protocol would not, and a later "fix commit 1" commit is churn a reviewer must subtract. Alternative rejected: a fourth "move Glimmer onto per-call forwards" commit.
- **Reuse `deploy`'s port, not a fresh port.** `deploy` already ported the same three files onto `6b68b9b4`. `main` has not changed those interfaces since, and the port passed GPU tests and a c16 export on the fork. Alternative rejected: re-porting from the PR head, which repeats work with no new information.
- **Glimmer owns its attention, and Spark returns to upstream's text.** `main`'s Spark decoder, `qualify/muse_spark_logits.py`, and the Spark CUDA tests use the bound-buffer attention, so widening Spark's file for a per-call caller would either break Spark or leave the PR's Spark hunks unused. The fold-back is recorded in `docs/TODO.md`. Alternative rejected: keeping the PR's Spark widening (dead code on `T`), or porting Spark's attention (changes another recipe's behavior; the operator rejected it for `deploy`).
- **Take number 11, not a renumbering of upstream.** `main` shipped 10 for `padded_grid`, and cores exported upstream use it. Fork cores exported with Glimmer at 10 before 2026-11-14 were never upstream-supported, and the PR says so. An engine without this PR refuses an 11 core with "missing protobuf image profile".
- **The baseline uses the same interpreter on both sides.** Rebuilding a venv at `T`'s lock compiles FlashInfer from source, and a shared interpreter already isolates the branch's effect. Alternative rejected: a fresh `uv sync --locked` venv at `T`.

**Risks / Trade-offs**
- [`deploy`'s Glimmer files carry other fork-only behavior beyond `draft_model`/`draft_files`] → `git diff fdfbeb29 <commit-1 tree>` for every Glimmer path is read hunk by hunk, and each hunk is classified as port, rename, `mtp_only`, or PR-original. The static `git grep` and `kwcheck.py` gates catch names absent on `T`.
- [A shared-path resolution drops an upstream hunk] → `git diff T HEAD --stat` must list only the PR's 63 paths minus the two Spark attention files and `ignition/components/dflash2.py`, plus the three new Glimmer files, `docs/TODO.md`, and support files a recipe-wide test on `T` forces (`tests/cli/test_mtp_only.py`), each named in `logs/paths.md`. `git range-diff` against the old chain is read for every non-Glimmer path.
- [The force-push overwrites a newer remote head] → `--force-with-lease=pr/muse-glimmer:5264a5959137d5dcf881e54ac635aa59bd2f1471`.
- [Upstream moves again before publish] → if `T` is behind the tip at publish, `git merge-tree` against the new tip must be clean, otherwise rebase again.
- [The GPU-1 image's FlashInfer is the fork's pin, not `T`'s] → disclosed beside those results. They show the ported modules run on SM120; they do not qualify `T`'s pin.
